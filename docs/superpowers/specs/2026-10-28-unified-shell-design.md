# 统一外壳：管理台与工作台合一

日期：2026-10-28
状态：设计（待实现）

## 1. 意图与背景

这个网关页面是作者日常唯一的工作界面：一边看待办、生成汇报，一边检查网关跑得怎么样。
但今天它是**两个页面**（`admin.html` 由 `/` 提供、`workbench.html` 由 `/workbench` 提供），
两页只共享了 `workbench.css`，外壳各长各的。作者的原话是「侧边栏和工作台的设计很不统一，
也很反用户」。

不统一不是观感问题，有三处具体的行为冲突：

1. **同一种外观，两种动作。** 管理台左栏四项目是页内切视图（不换页、记 `gw-view`、
   数字键 1–4），第五项「工作台」却是真跳页。长得一模一样，点下去后果不同。
2. **同一组页面，两套编号。** 「工作台」在管理台里编号 05，到工作台页变成 02、
   「管理台」变 01。
3. **左栏下半截各写各的。** 管理台塞显示器整机同切、重启/停止、协议串；工作台是纯文字说明。
   遥测区一边 3 行 statline、一边 2×2 网格。主题按钮两页各写一份内联 `style`。

另有一个作者独立报告、实测确认的缺陷：**左栏文字竖排**（见 §3.2）。

**为什么现在做**：作者明确说「这个整个页面就是我日常工作的工作台」，两页割裂每天都在付成本。
**成功的模样**：打开一个地址，左栏只有一件事要理解——「我在哪」，不再需要记住哪种点击会换页。

## 2. 目标 / 非目标 / 反目标

**目标**

- 一个页面承载全部六个视图：待办、汇报、总览、统计、诊断、配置。
- 左栏两级：工作台（日常主入口，在上）与管理台（组，可折叠，在下），子栏目在视觉上明确从属。
- 清除左栏任何位置的中文逐字竖排与拉丁文溢出裁切。
- 左栏两页同构——合并后自然成立，因为只剩一个页面。
- `#hash` 深链、`gw-view` 记忆、旧链接全部继续可用。

**非目标**

- 不改任何服务端能力：`/v1/*`、`/admin/*`、统计口径、报告管线、待办数据层一律不动。
- 不引入构建步骤、包管理器、框架、外部 CDN 或字体。
- 不重做各视图内部的信息设计（表格列、图表、表单字段保持原样）；本次只统一外壳与左栏。
  唯一触碰视图内部的是 `.sechead .idx` 的文本（§3.1 末段），属外壳范畴的编号统一，
  不含信息设计变更。
- 不动主题色板与深浅色规则。

**反目标（techincally 能跑也算失败）**

- 合并后出现「在待办页却还在每 3 秒拉日志和 30 天统计」的隐性开销。
- 合并后某个功能悄悄消失（显示器切换、重启/停止、下载 .md、skip 类键盘可达性）。
- 合并后单页脚本内部出现同名变量互相覆盖（`esc`/`apiFetch`/`editingId` 这类），表现为
  偶发的错误转义或编辑态串台——比崩溃更难查。
- 左栏靠把字号改小硬塞下长文本（作者要的是格子合理，不是字更小）。

## 3. 现状诊断

### 3.1 结构现状

| | 管理台 `/` | 工作台 `/workbench` |
|---|---|---|
| 左栏导航 | 4 个页内按钮 + 1 个跳页链接 | 2 个跳页链接 |
| 左栏遥测 | 3 行 statline | 2×2 网格 `rail-stats` |
| 左栏底部 | 显示器整机同切 / 重启 / 停止 / 协议串 | 「Sources」文字说明 |
| 主区 | 4 个 `.view`，按 `data-view` 切换 | 2 个 `.sec`，永远同时可见 |
| 轮询 | 3 秒拉 `/healthz` + `/admin/log` + `/admin/stats` | 无轮询，仅 `focus` 时刷 |

主区小节编号也串：总览 01–04、统计 02–03、诊断 03、配置 04——同一个数字在不同视图指不同东西。
**处理（我的判断）**：保留 `.sechead .idx` 这个视觉元素，但**每个视图内部从 01 重新递增**，
不再与左栏视图编号联动。理由是左栏已改为无编号的两级结构（§5.1），主区编号退回它本来的
作用——「本页第几块」，不再是「第几个视图」。这是唯一需要改动各视图标记的项：只改
`.sechead .idx` 的文本，不动任何信息设计。

### 3.2 左栏竖排的根因（实测）

用 Chrome headless 对运行中的实例截图（`/tmp/cgp-shots/live.png`）并量算：

- 左栏 `--rail-w: 216px`，`.rail` 内边距 `26px 16px 18px 22px` → 内容宽 **178px**。
- `.rail-controls` 是 `display:flex; gap:7px`，三个「整机同切」按钮各 `flex:1`
  → 每个 **(178 − 14) / 3 = 54.7px**，减按钮内边距 `6px 8px` → 内容 **38.7px**。
- 中文的 min-content 宽度是 **1 个字符**（可在任意字间断行），所以按钮能缩到 54px；
  38.7px 按 11.5px 字号只容得下约 3.4 个中文字 → **中文逐字换行，视觉上就是竖排**。
- 拉丁文（`MacBook`、`Windows`）min-content 是整个词，按钮缩不下去 → 整行溢出 178px，
  被 `.rail` 的 `overflow-y:auto` 裁掉（截图里按钮右侧被切）。

同一类问题另有两处：

- `.rail-proto`（`openai (passthrough / translated) · anthropic messages (direct / translated)`）
  带 `word-break: break-all`，在 140px 左右的宽度里逐字符折断，呈竖排细柱。
- `.viewbtn` 每行同时放中文名（宋体 14.5px）+ 英文小标（mono 8.5px，字距 .18em），
  如 `Traffic · Perf`；两者叠加把行撑宽，窄屏（≤900px 顶栏）下更明显。

**结论**：这是布局契约缺失，不是字体选择问题。修复必须靠「单项单行 + 可收缩 + 省略号」，
而不是缩字号。

## 4. 方案

考虑过三条路，前两条已在与作者的对话里被排除：

**A. 单页 + 单段内联脚本（已选）** — `admin.html` 扩成整页应用，`workbench.html` 删除，
两段脚本合并为一段（重名逐个归并）。零依赖风格不变，无新路由机制，`install.sh` 只改文件清单。
代价：单文件约 2400 行、脚本周约 1500 行。

**B. 单页 + 拆 ES 模块**（`lib/ui/*.mjs` + `<script type="module">`）— 每个模块 200–400 行，
长期更好维护。代价：破例离开「页面自包含」的现状，要新增静态路由与 MIME 处理，
模块加载失败时页面静默白屏、排查更绕。

**C. 保持两页，只对齐外壳** — 代价最小，但「两页」这个割裂本身正是问题来源，不解决根因。

**选 A**，理由：本次问题是设计统一，不是架构问题；先合一，等真觉得脚本难改再拆不迟（B 随时可以
在此基础上做增量重构）。C 会留下作者已经点名的割裂。

## 5. 详细设计

### 5.1 信息架构

左栏两个分组，六个视图：

```
◈ 个人工作台
GATEWAY · WORKBENCH

● 运行中                    ☾
运行 12秒 · 鉴权 已启用
今日 128 次 · 上游 3

  工作台                        [组头 · 默认展开]
    待办                    3    → #todos   （首屏默认）
    汇报                    5    → #report
  管理台                    1    [组头 · 默认收起]
    总览                         → #overview
    统计                         → #traffic
    诊断                         → #test
    配置                         → #providers
```

- **组头**：`工作台`/`管理台` 用宋体 600、略大于子项，左侧一个折叠箭头；点击只切换展开，
  不导航。组头本身也可带一个汇总徽标（管理台 = 异常 provider 数）。
- **子项**：缩进 22px，字号降一档，左侧一条 1px 导轨线贯穿（`::before`），表达从属。
- **当前项**：琥珀左游标 + 淡琥珀底（沿用现有 `.viewbtn.active::before` 语言）。
- **徽标**：复用 `.vbadge`。待办 = 未完成数（pending + in_progress）；汇报 = 存档份数；
  总览 = 凭证异常 provider 数（红）；诊断 = 最近 80 行里的错误行数（红）。统计/配置不带徽标
  （统计的「今日请求」已在遥测区，避免重复）。
- **左栏遥测**：三行——状态灯 + 状态文字（含主题按钮）、`运行 x · 鉴权 y`、`今日 n 次 · 上游 m`。
  工作台原 2×2 网格里的**「进行」**并入待办徽标（未完成数）；**「今日完成」**改放**待办视图的
  小节说明行**（`.sechead .note`：「进行中 3 · 今日完成 5」）——它在待办页才有决策价值，
  常驻左栏是浪费。**「汇报存档」**即汇报徽标，两处数字同源。
- **启动时的一次性预取（种子）**：左栏徽标要在任意落地视图都显示真值，所以启动时**各拉一次**
  `/v1/todos`、`/admin/report/list`、`/admin/log`、`/admin/providers`、`/v1/models`。
  这些是回环请求、各自一次、无重复成本，与「每 3 秒常驻拉取」的隐性开销不是一回事。
  预取失败不阻塞渲染，徽标暂显 `–`，进入对应视图时自然补上。
- **展开状态**：`localStorage` 键 `gw-groups`（`{"workbench":true,"console":false}`）。
  默认工作台展开、管理台收起。**当前视图所属组强制展开**（进了 `#traffic` 却看到组是收着的，
  会让人以为走错页）；用户随后手动收起则尊重手动操作，直到切换视图再次触发。
- **左栏底部**：只保留主题切换按钮（移到遥测区右侧，见上）。显示器整机同切、重启/停止、
  协议串全部移出左栏（去向见 §5.6）。
- **不出现英文小标**：`待办/汇报/总览/统计/诊断/配置` 都是 2 字，单行不折。移除 `.ven`
  既是竖排修复的一半，也让两级结构更清爽。主区 `.sechead .en` 保留（那里有横向空间）。

### 5.2 路由与深链

视图 6 个：`todos`、`report`、`overview`、`traffic`、`test`、`providers`。

- 每个视图是 `<section class="view" data-view="...">`，非当前视图 `display:none`。
- 导航项是 `<a href="#todos">` 这样的**真链接**（可中键新开、可复制、可 Tab 到），
  `hashchange` 驱动切换；`setView()` 只改 DOM 与 `history.replaceState`。
- 别名的历史映射保留并扩展：`latency → traffic`、`log → test`、`stats → traffic`、
  `workbench → todos`、空 hash → `todos`。
- `#stats-7` / `#stats-30` 旧形态继续落统计页并预选区间（现有逻辑保留）。
- **`/workbench` 路由继续提供同一份 `index.html`**（旧书签不废）。它**强制**落 `todos`，
  优先于 `gw-view` 记忆——旧书签的语义是「我要工作台」，落到上次看的管理台视图就是违约；
  落地后用 `history.replaceState` 把地址改写成 `/#todos`，刷新与再收藏都保持一致。
- **`/`（及 `/admin`）**：首次访问默认 `todos`；之后按 `gw-view` 记忆上次视图。
- 数字键 1–6 按左栏从上到下的顺序映射（待办、汇报、总览、统计、诊断、配置），
  输入控件内不抢键（现有守卫保留）。

### 5.3 左栏布局契约（竖排修复）

这是本次的硬性规则，写进 `theme.css` 的注释，后续改动照此执行：

1. **左栏内不放横向并排的多个文字控件。** 需要并列选项时，纵向排列，一项一行。
2. **每个左栏行是单行。** 文字容器 `min-width: 0` + `white-space: nowrap` +
   `overflow: hidden` + `text-overflow: ellipsis`；宽度不够时省略，绝不换行。
3. **不做逐字符断行。** 禁用 `word-break: break-all`；确需截断的长串（URL、协议名）
   一律走规则 2 的省略号。
4. **遥测行同样适用**：`value` 用 `font-variant-numeric: tabular-nums` + `nowrap`，
   超长一律省略并保留 `title` 全文。
5. **窄屏（≤900px）**左栏折叠为顶栏时，导航项横向排列且 `white-space: nowrap` +
   横向滚动，不换行（现有 `.views` 行为保留并加固）。

配套：`.rail` 宽度维持 216px（行变单行后富余），不靠缩字号解决拥挤。

**移除项（竖排的具体来源）**：`.rail-controls` 横向按钮组（显示器同切、重启/停止）、
`.rail-proto`（协议串，`word-break:break-all`）、`.viewbtn .ven`（英文小标）。
其中协议串与显示器同切在 §5.6 找到新家，不是删除。

### 5.4 轮询模型

现管理台每 3 秒无条件拉三个接口；现工作台完全不轮询。合并后按视图决定：

| 请求 | 频率 | 条件 |
|---|---|---|
| `/healthz` | 3s | 永远（左栏状态灯、运行时长、今日请求、上游数都要活） |
| `/admin/stats` | 3s | 仅在 `overview` 或 `traffic` 视图可见时 |
| `/admin/log` | 3s | 仅在 `test` 视图可见时 |
| `/admin/monitors` | 6s（服务端另有 5s 缓存） | 仅在 `overview` 视图可见时（现有逻辑保留） |
| `/v1/todos` | 无轮询 | 进入 `todos` 视图时拉一次 + `focus` 时静默刷新（现有行为保留） |
| `/admin/report/list` | 无轮询 | 进入 `report` 视图时拉一次 + 生成中 2s 轮询 job（现有行为保留） |

- 左栏「今日 n 次」数字仍由 `/healthz` 提供（`/healthz` 不含统计……需要核对）；
  若 `/healthz` 不含，则该数字改由徽标承载，或允许在非统计视图下不更新。
  **实现时确认**：`admin.html:793` 的 `railTodayReq` 来自 `/admin/stats` 的 `today.req`。
  因此左栏今日数字改为**由 `/admin/stats` 更新，仅在其被拉取时更新**；离开统计视图后
  数字停在最后一次的值，不显示为「实时」。若作者认为必须实时，则 `/admin/stats` 常驻
  （代价是待办页也每 3 秒拉 30 天统计）。默认取前者，实现时若体积可忽略可改常驻——
  以实测响应体积为准（`/admin/stats` 在 30 天满量数据下是本次唯一可能变大的请求）。
- 视图切换时立即触发一次该视图所需请求（不等下一个 tick），避免切过去看到空壳。
- 定时器：单个 3s ticker，按需分支，不叠加多个 `setInterval`。
- **报告生成中的 2s job 轮询不受视图影响**：生成是有界时长的进行中任务，切到别的视图
  也应继续推进并在完成时提示（与「现有行为保留」一致）。

### 5.5 组件与命名归并

合并两段脚本时必须逐项处理（不做则静默出错）：

| 冲突 | 管理台现版 | 工作台现版 | 归并后 |
|---|---|---|---|
| `esc()` | 只转 `&` `<` | 转 `&` `<` `>` `"` | 取工作台版（更严）。管理台里手补的 `.replace(/"/g,'&quot;')` 变成无害冗余，保留或清理均可 |
| `apiFetch()` | 总是加 Bearer | 仅 `/v1/` 加 + 401 重取一次 | 取工作台语义（`/v1/` 加 + 401 重取）；管理台所有 `apiFetch` 调用目标都是 `/v1/*`，行为不变 |
| `loadToken()` | 同名同义 | 同名同义 | 保留一份 |
| `editingId` | 改供应商的 id | 改待办标题的 id | 拆成 `provEditingId` / `todoEditingId` |
| `applyTheme()` | 无参，读 `themeMode` | 带 mode 参数 | 取管理台版（含 `prefers-color-scheme` 变化监听） |
| 在线状态 | `render()` 里 `sState` | `setOnline()` 单独维护 | 统一：`render()` 一处决定状态灯与文字；`setOnline(false)` 只作为请求失败的旁路 |
| 错误提示 | `providerBanner` + `stopBanner` | `errBanner` | `providerBanner`（凭证异常，常驻）+ `errBanner`（操作失败，8s 自动消失 + 点击关闭）+ `stopBanner`（已停服） |
| `safe()` | 无 | 有（async 回调兜底） | 全站采用 |
| `fmtDur` / `fmtTime` / `fmtTimeFull` | 有 fmtDur | 有 fmtTime/fmtTimeFull | 并存（名不冲突） |

另需确认无遗漏：合并后对整段脚本做一次「同名标识符」静态扫描（`grep` 出所有
`function|const|let` 顶层声明，人工比对重复），作为实现的验收项而非事后补救。

**严格模式**：工作台脚本是 `'use strict'`，管理台不是。合并后**统一用严格模式**（工作台那段的
纪律更好，且能提前暴露隐式全局）。若管理台段有依赖非严格行为的写法（极少见：未声明赋值、
`with`、八进制字面量），在合并时一并修掉，而不是为此放弃严格模式。

### 5.6 移出的功能去向

| 原位置 | 新位置 |
|---|---|
| 左栏「整机同切」输入源按钮组 | 总览页「显示器输入源」卡顶部，一行横向按钮组（主区宽度充足，不挤） |
| 左栏「重启服务」「停止服务」 | 配置页底部新增「服务控制」小节（一行两按钮 + 一句说明） |
| 左栏协议串 `sProto` | 总览页「订阅上游」卡的小节说明行（`.sechead .note`） |
| 工作台左栏「Sources：Claude Code · zcode · opencode · Cursor」 | 汇报页小节说明行 |
| 工作台 skip link「跳到报告区」 | **移除**。汇报已是独立视图，左栏一键可达，skip link 的前提（同页大量行内按钮淹没 Tab 序）不再成立 |

### 5.7 文件与安装

- `admin.html` → **`index.html`**（它不再是「管理台」，而是整个应用）。改名理由：名字要对得上
  内容；代价是 `server.mjs`、`install.sh`、测试、README、CLAUDE.md 各改一处引用。

## 6. 约束（不可违背）

- **零依赖**：不新增 `package.json`、不加外部资源。字体仍只用系统字体栈。

  校验——合并页面不改任何服务端鉴权逻辑；页面侧 `esc()` 统一后只增强不减弱转义。
