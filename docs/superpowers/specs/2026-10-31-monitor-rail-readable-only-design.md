# 左栏切屏条只显示「读得出来」的屏

日期：2026-10-31 · 小改动

## 意图

左栏底部（`#railFoot`）是**快捷切源条**，不是状态面板。屏读不到时它仍渲染一行灰按钮
（`data-mnext=""`，点一下变成「重试读取」），于是拔掉显示器后左栏会长期挂着几行点不出
效果的按钮——本机的两台 AOC 当前就没接上，左栏正挂着两个「读失败」。

因此：**左栏只显示当前读得出输入源的屏**；读不到的仍完整列在「总览 → 04 显示器输入源」
里（含 m1ddc 错误原文），诊断信息一个字不少，只是不占侧栏。

## 范围

- 只改 `index.html` 的 `renderMonitors`（左栏渲染分支）与对应注释；后端、路由、配置格式均不动。
- `#monList`（总览页）**继续显示全部配置屏**，包括读失败的——错误原文必须有个地方能看见。
- 「全部 → x」按钮仍下发到 `providers.json` 里配置的全部屏（后端 `resolveDisplays` 缺省行为），
  不改成只写可读屏——那需要服务端支持一次切多块屏，属另一个改动。

## 我的取舍（可以直接否）

1. **连续两次读失败才隐藏**，不是一次失败就藏。DDC/I2C 读偶发超时，一次抖动就让按钮消失、
   十秒后又冒出来，比常驻更烦；两次约等于 20 秒，拔线后很快消失，偶发抖动不受影响。
   计数只在页面内存里，刷新页面清零（刷新后若恰好失败一次，那一次仍会显示）。
2. **「全部 → x」的选中态只按可读屏计算**。现在 `atAll = n === all.length`，只要有屏读不到，
   这个高亮永远不会亮——即便能读的那几块都已在目标输入源。改成与可读屏数量比较。
3. 读失败且尚未到两次的屏，仍保留「点一下 = 重试读取」的旧行为，不新增交互。

## 非目标

- 不改成按 `m1ddc display list` 枚举硬件（已讨论后放弃）。
- 不做「插上就自动出现、拔掉就自动消失」的配置同步。
- 不隐藏「全部 → x」整组（它作用于配置屏，不依赖单屏读取结果）。

## 验收

- 配置里两块屏、都能读 → 左栏两行，行为与现在一致。
- 连续两次读失败 → 该行从左栏消失；「总览」页该屏一行仍在，带错误原文。
- 全部屏都读不到 → `#railFoot` 整体隐藏（沿用 `all.length` 判空即可）。
- 一块可读、一块不可读 → 左栏只有一行；「全部 → x」能正确高亮。
